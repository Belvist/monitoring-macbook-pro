# MacScope Native — монитор macOS

Нативное приложение на SwiftUI в отдельном окне Mac. Не открывает браузер и не поднимает веб-сервер для интерфейса.

## Установка / запуск

1. Распакуй архив на macOS 13 или новее.
2. Для первой сборки запусти `Собрать_на_Mac.command`. В дальнейшем открывай `MacScope.app` как обычное приложение.
3. Для компиляции необходимы **Xcode Command Line Tools** или Xcode со встроенным macOS SDK. Если их нет: `xcode-select --install`.

В пакете находятся SwiftUI-исходники и macOS `.app` с механизмом первой локальной компиляции. Архив подготовлен на Linux, поэтому **предварительно скомпилированного Mach-O бинарника внутри нет**. После успешной первой сборки нативный исполняемый файл сохраняется внутри `.app` и повторная компиляция не требуется.

Исправление версии 1.1: компиляция вызывается с **явным `-sdk` и `-target arm64-apple-macosx13.0`** (для Intel — `x86_64-apple-macosx13.0`), чтобы не полагаться на автоматическое определение целевой версии и SDK компилятором. Ошибка `unable to load standard library for target` может возникать, если вызывать бинарник `swiftc` напрямую без SDK.

Исправление версии 1.2: CPU считается по дельтам суммарного cputime между обновлениями (как Activity Monitor), а не по lifetime-среднему `ps %cpu`. Занятая RAM = active + wired + compressed (файловый кэш больше не считается занятой). Сеть считается по всем интерфейсам кроме loopback.

Исправление версии 1.3: память процессов берётся из `top MEM` (полный footprint: резидентная + сжатая + swap + GPU-память MPS/Metal), а не из `ps rss`. Процесс с большой GPU-памятью больше не выглядит как «400 МБ вместо 6 ГБ».

Изменение версии 1.4: настоящее снятие задачи — «Убить полностью» завершает всё дерево процессов (SIGTERM, несдавшимся — SIGKILL) с проверкой результата. Кнопка есть и в «Сайтах и портах», и в строках «Процессов». Остальные метрики сверены: swap, сеть, диск и сервисы совпадают с системными.

Изменение версии 1.5: убийство требует двух подтверждений (выбрать → подтвердить), чтобы нельзя было снести процесс одним случайным кликом.

## Что показывает

- **Обзор:** CPU, приблизительно используемую RAM, сжатую память, swap, свободное место, сетевой трафик и графики.
- **Сайты и порты:** процессы с открытыми TCP LISTEN-портами, имя проекта по рабочей папке, заголовок локальной HTTP-страницы, PID, использование CPU/RAM. Базы данных обозначаются как TCP-сервисы, без ложного названия сайта.
- **Процессы:** процессы macOS, команда запуска, CPU, RSS, PID.
- **Память и диск:** RAM, swap, SSD и известные каталоги больших технических данных.
- **Действия:** открыть локальный сайт, назначить отображаемое имя порту, мягко остановить **свой** процесс (SIGTERM) или убить полностью всё дерево процессов (SIGTERM → SIGKILL) после двух подтверждений. Чужие/системные процессы и сам MacScope защищены от завершения.

## Честные ограничения

- Собранный macOS бинарник и нативный интерфейс не тестировались на реальном Mac в этом окружении. Проверены Swift-синтаксис, отдельные тесты системного парсинга, правильность аргументов команды сборки и формат пакета.
- Для получения метрик используются `ps`, `lsof`, `sysctl`, `vm_stat` и `netstat`. Некоторые чужие процессы macOS могут скрываться системными ограничениями.
- CPU считается по изменению суммарного времени процессов за интервал обновления (первый замер после запуска — грубая оценка). Системная RAM — active + wired + compressed, как у Мониторинга системы; файловый кэш в занятую не входит. Память процесса — полный footprint (включая сжатую, swap и GPU), как колонка памяти в Мониторинге системы. HTTP-заголовок страницы не гарантирует, что сайт работает без ошибок.
- Монитор периодически проверяет первые 20 локальных адресов HTTP; запросы могут попадать в логи локальных серверов. Облачной телеметрии нет.
- Приложение не нотарифицировано и не подписано сертификатом Apple Developer; скрипт пробует выполнить локальную ad-hoc подпись после успешной сборки.

## Если первая сборка не прошла

Запусти `Собрать_на_Mac.command` и пришли полный вывод ошибки. Лог находится здесь:

`~/Library/Logs/MacScope-build.log`

Для диагностики окружения:

```sh
xcode-select -p
xcrun --sdk macosx --show-sdk-path
xcrun swiftc --version
```

Исходники доступны в `Source/` и `MacScope.app/Contents/Resources/`. Для тестов без SwiftUI:

```sh
swiftc -swift-version 5 Source/CoreLogic.swift Source/MacCollector.swift Tests/main.swift -o /tmp/macscope-tests
/tmp/macscope-tests
```
